# 급식레벨업 성장·급식 경험 UX 감사

- 감사일: 2026-08-30
- 대상 기준선: codex/ios-growth-meal-polish-v2 분기 시작점의 iOS 1.2/build 33 후보
- 공개 기준선: App Store 1.1, 번들 ID com.h19h29.naymnaymlevelup
- 목적: 구현 전 P0/P1/P2 우선순위와 검증 가능한 완료 기준 확정
- 범위: 오늘의 숲, 급식 달력, 식사 기록, 성장, 도감, 보호자 연결, 공개 스토어 표현

## 결론

현재 1.2 후보는 Core Data 기반 Rebuild, 오프라인 우선 급식 조회, 원장형 XP, 성장 정책 JSON, 첫 제작 마스코트 리그처럼 재사용할 기반이 충분하다. 그러나 그대로 출하하면 요구된 12단계 대신 14단계가 노출되고, 8–14단계가 같은 7단계 그림으로 보이며, 주간·월간 날짜에서 공통 일 상세로 이동하지 못한다. 식사 기록에는 대표 영양소 피드백이 없고 알레르기 위험 메뉴에서 화면 선택지와 저장 검증이 일치하지 않는다.

따라서 이번 구현의 출하 차단선은 다음 다섯 가지다.

1. 공개 1–7 임계값과 사용자 XP를 보존하면서 성장 정책을 정확히 12단계로 고정한다.
2. 오늘·주간·월간이 동일한 날짜 상세를 사용하고, 선택 날짜를 오늘이나 월 첫 급식으로 대체하지 않는다.
3. 메뉴명 기반 대표 영양소 피드백을 식사 기록 확인 단계에 연결하되, 개별 음식의 정량 수치를 추정하지 않는다.
4. 알레르기 메뉴의 안전 행동과 저장 검증을 하나의 규칙으로 맞추고, 상태 변경 시 중복 기록·중복 XP를 막는다.
5. 공개 1.1의 XP, 기록, 사진, 배지, 선택 스킨, 보호자 연결을 보존한다.

## 근거와 기준선

### 공개 앱과 스토어

2026-08-30 공식 App Store 페이지에서 공개 버전은 1.1이며 iOS 16 이상, 한국어, 교육 카테고리로 확인했다. 공개 스크린샷은 다음 네 장 순서다.

1. 01-today-forest
2. 02-meal-recording
3. 03-growth
4. 04-growth-collection

스토어의 접근성 섹션은 개발자가 지원 접근성 기능을 아직 표시하지 않았다고 안내한다. 현재 저장소의 release/AppStoreMetadata/ko-KR.md와 JSON은 1.1/build 30 기준이지만 Xcode 프로젝트는 1.2/build 33 후보다. 메타데이터에 적힌 기능 문구도 현재 후보의 일간·주간·월간 구조와 완전히 일치하지 않는다.

### 소스와 데이터

- 공개 1–7 성장 임계값은 0, 80, 180, 320, 500, 720, 1000 XP다.
- 현재 후보의 growth-policy.json은 14개 임계값과 14개 이름을 갖는다.
- 현재 GrowthView와 CollectionView는 8단계 이상에도 7단계 마스코트 이미지를 재사용한다. 도감에는 “캐릭터 14”가 고정 문구로 들어가 있다.
- 성장 단계는 총 XP에서 계산되며 Core Data에 최고 단계가 별도 저장되지 않는다. 그러므로 미출시 14단계 번호 자체는 마이그레이션해야 할 사용자 데이터가 아니다.
- Rebuild 마이그레이션은 프로필, 급식 기록, 사진 기록, 보호자 연결과 XP 합계를 검증하지만, 공개 버전의 선택 스킨과 기존 배지 가시성은 Rebuild 저장 구조에서 명시적으로 보존되지 않는다.
- Rebuild 급식 모델에는 날짜, 메뉴, 알레르기 코드, 영양 총량, 태그, 원문이 이미 있다. NutritionRuleEngine과 nutrition-rules.json도 존재하지만 현재 식사 기록 UI에는 연결되지 않았다.
- MealScheduleCalendar.weekDates는 월–금 5일만 반환한다. 주간·월간 날짜 선택은 선택 날짜 갱신과 인라인 정보 표시에 머물고 공통 날짜 상세로 이동하지 않는다.
- RebuildEatingStatus에는 여섯 상태가 있으나 TodayForestViewModel은 half를 노출하지 않는다.
- 알레르기 코드가 있는 메뉴에서 화면은 한 입만 비활성화하지만 RecordMealUseCase는 allergyAvoided 외 상태를 거부한다.
- 기록 식별자에 상태가 포함되어 상태를 바꾸면 같은 날짜·메뉴의 활성 기록이 여러 개 생길 수 있다. XP 중복 지급은 방어하지만 현재 상태의 단일성은 보장하지 않는다.

### 시각 기준선

현재 공개용 네 장은 밝은 숲과 큰 마스코트로 세계관은 잘 전달한다. 반면 화면 대부분이 크림색 카드와 녹색 텍스트·버튼으로 구성되고, 급식은 글머리표 목록에 머문다. 식사 기록 시트는 비슷한 카드와 연녹색 상태 버튼이 길게 반복되고, 성장 도감은 동일 실루엣의 긴 세로 목록이다. 월간 화면은 7열 개요를 제공하지만 작은 글자와 높은 정보 밀도로 실기기 가독성이 낮다.

## UX 진단

### 잘 유지할 것

- 첫 제작 숲 장면과 마스코트 1–7은 앱 정체성을 가장 강하게 만든다.
- 원장형 XP와 JSON 성장 정책은 단계 변경을 데이터 손실 없이 처리하기 좋은 기반이다.
- 날짜·메뉴·알레르기·영양 정보가 한 급식 도메인에 이미 모여 있다.
- 급식 로드 상태에 캐시, 갱신, 실시간, 없음, 실패가 이미 구분되어 있다.
- 48pt 최소 터치 영역과 시스템 글꼴 기반 토큰은 접근성 확장의 좋은 출발점이다.
- 공개 버전 Codable 기본값과 재계산 로직은 오래된 저장 데이터 복구에 유리하다.

### 주요 마찰

- 오늘의 핵심 행동이 “이번 식사에서 무엇을 해 볼까”보다 오프라인 안내와 일반 카드에 묻힌다.
- 날짜 탐색에서 사용자가 고른 날과 실제 상세 화면의 날짜를 강하게 연결하는 경로가 없다.
- 한 메뉴를 먹은 뒤 얻는 학습 보상이 XP 숫자뿐이라 행동과 영양 학습의 연결이 약하다.
- 성장 후반 단계는 이름만 늘고 실제 모습은 같아 수집 동기가 급격히 약해진다.
- 알레르기 안전 규칙이 UI와 저장 계층에서 달라, 사용자가 선택한 뒤 오류를 만날 수 있다.
- 작은 월간 글자와 색 중심 상태 구분은 Dynamic Type·VoiceOver에서 의미 손실 위험이 있다.

## 우선순위

### P0 — 출하 전 반드시 해결

#### P0-1. 14단계 후보를 정확히 12단계로 정리

문제:

- 승인된 범위는 정확히 12단계인데 현재 정책·도감 문구·테스트는 14단계다.
- 8–14단계가 모두 7단계 그림을 재사용해 “새 캐릭터”라는 표현과 실제 화면이 다르다.

완료 기준:

- 정책, UI, 테스트, 접근성 라벨에 단계 수 12가 단일 진실로 사용된다.
- 공개 1–7 이름과 임계값은 그대로 유지한다.
- 모든 기존 XP 값은 수정하지 않고 같은 XP에서 공개 1.1보다 낮은 단계가 되지 않는다.
- 미출시 14단계 후보의 소재는 8–12의 이름·배경·보상으로 편집 통합하며 13·14라는 사용자 상태를 마이그레이션하지 않는다.

#### P0-2. 날짜 선택과 실제 급식 상세 연결

문제:

- Rebuild 주간은 월–금만 보여 주고 주간·월간 선택은 공통 일 상세로 이동하지 않는다.
- 로드 결과를 메뉴 유무로 축약하면 “급식 없음”과 “불러오기 실패”가 섞인다.

완료 기준:

- 주간은 월–일 7일이며 주말은 숨기지 않고 시각적으로만 보조 처리한다.
- 오늘·주간·월간 모두 동일한 MealDayDetail 화면과 정확한 dateKey를 사용한다.
- 선택 날짜에 데이터가 없으면 그 날짜만 조회하고 오늘 또는 월 첫 급식으로 대체하지 않는다.
- 캐시·갱신·실시간·급식 없음·실패가 날짜별로 구분된다.

#### P0-3. 식사 기록 피드백과 알레르기 안전 규칙 통합

문제:

- 기존 영양 규칙 엔진이 UI에 연결되지 않아 식사 후 학습 보상이 없다.
- 화면 선택지와 저장 검증이 다르며 half 상태도 누락됐다.
- 상태가 식별자에 포함되어 동일 날짜·메뉴의 활성 기록이 중복될 수 있다.

완료 기준:

- 여섯 상태를 모두 제공한다.
- 상태 선택 → 대표 영양소 영향 확인 → 저장 확인 → XP 결과의 단일 흐름을 사용한다.
- 알레르기 위험 메뉴는 안전 회피 행동을 기본으로 하며 허용되지 않는 상태는 선택 전에 막는다.
- 같은 dateKey와 정규화 메뉴 키에는 현재 상태가 하나만 남고, 수정은 기존 사용자 기록을 삭제하지 않는 방식으로 이력을 보존한다.
- 개별 음식에는 대표 영양소 유형과 쉬운 설명만 제공하고, 근거 없는 g·mg·kcal 수치를 만들지 않는다.

#### P0-4. 공개 사용자 데이터 보존 범위 보강

문제:

- 현재 검증은 XP와 주요 기록에 강하지만 공개 선택 스킨과 기존 배지의 Rebuild 가시성을 보장하지 않는다.

완료 기준:

- 프로필, XP 구성요소와 합계, 도전 기록, 급식 기록, 사진, 배지, skin-1…skin-7 선택, 보호자 링크·공유 상태가 이관 전후 비교 대상에 포함된다.
- 마이그레이션 실패 시 성공 상태를 기록하지 않고 기존 저장소를 삭제하지 않는다.
- 누락·손상된 새 에셋은 데이터 손실이나 크래시를 일으키지 않고 검증된 기존 에셋으로 대체 표시한다.

#### P0-5. 릴리스 진실 공급원 정리

문제:

- README는 Rebuild가 Release에서 꺼져 있다고 적지만 프로젝트 Release 조건에는 NATIVE_REBUILD_RELEASE_ENABLED가 있다.
- 1.1 메타데이터, 1.2 프로젝트 값, 14단계 Figma 기록이 서로 다른 범위를 가리킨다.

완료 기준:

- 런타임 진실은 최신 Rebuild 후보, 호환성 진실은 공개 1.1 저장 모델, 성장 진실은 승인된 12단계 정책으로 문서화한다.
- Figma의 14단계 보드는 참고 기록이며 구현 진실이 아님을 표시한다.
- 실제 출하 전 버전·빌드·메타데이터·컴파일 조건을 한 번에 검증하는 체크를 둔다.

### P1 — 이번 개선에서 해결

#### P1-1. 녹색·크림 단조로움과 카드 과잉

녹색은 성장·성공 의미로 좁히고, 오늘 미션·영양소·알레르기·성장 단계에 따뜻한 노랑, 코랄, 보라, 하늘, 인디고, 민트의 의미 색을 배정한다. 기존 AppColors와 RebuildDesignTokens를 확장해 사용하며 별도 대형 테마 프레임워크를 만들지 않는다. 모든 정보를 같은 흰 카드로 감싸지 않고 배경 구역, 대표 카드, 인라인 행의 세 위계만 사용한다.

#### P1-2. 텍스트 급식 목록을 음식 중심으로 개선

메뉴 행에 대표 음식 아이콘, 메뉴명, 알레르기 표식, 대표 영양소 칩을 제공한다. 아이콘은 화면의 장식이 아니라 56–64pt의 인지 단서로 쓰고, 에셋이 없을 때는 음식 카테고리 SF Symbol로 대체한다.

#### P1-3. 성장 로드맵과 도감 밀도 개선

현재 단계·다음 단계·전체 12단계를 한눈에 이해하게 하고, 단계별 실제 변화는 마스코트 액세서리·배경·프레임을 함께 사용한다. 도감은 동일한 대형 세로 카드를 반복하지 않고 2열 그리드와 선택 상세를 사용한다. 잠금은 실루엣과 자물쇠 라벨을 함께 사용해 색에만 의존하지 않는다.

#### P1-4. 식사 기록 시트 길이와 결과 피드백 개선

여섯 상태를 큰 세로 카드로 반복하지 않고 아이콘이 있는 선택 그리드 또는 압축 행으로 제공한다. 어려웠어요의 이유 입력은 해당 상태에서만 펼치고, 영양 확인은 선택 후 한 장의 요약으로 제시한다.

#### P1-5. 가독성과 접근성

- 월간 10pt 고정 글꼴을 제거하고 Dynamic Type에서 축약 규칙을 적용한다.
- 모든 아이콘에 의미 라벨을 제공하고 장식 이미지는 VoiceOver에서 숨긴다.
- 단계·급식 상태는 색과 함께 텍스트·아이콘·모양으로 구분한다.
- Reduce Motion에서 축하 애니메이션을 정적 상태로 대체한다.
- iPhone SE 폭에서 상태 선택과 달력이 가로로 잘리지 않아야 한다.
- 48pt 최소 터치 영역과 충분한 대비를 유지한다.

#### P1-6. 공개 스크린샷 이야기 보강

기존 네 장의 강한 숲 세계관은 유지하되, 후속 스토어 세트는 다음을 분명히 보여야 한다.

1. 오늘의 급식과 한 가지 실행 미션
2. 음식 아이콘·대표 영양소가 있는 기록 흐름
3. 월–일 날짜 탐색과 선택 날짜 상세
4. 정확히 12단계인 성장 로드맵과 실제로 다른 후반 단계
5. 알레르기 안전 행동과 보호자 연결

네 장 제한을 유지한다면 1, 2, 3, 4를 우선하고 알레르기·보호자 연결은 설명 문구나 추가 기기 프레임으로 검증한다. 스토어 접근성 지원 항목은 실제 테스트가 끝난 기능만 선언한다.

### P2 — P0/P1 안정화 뒤 고려

- 급식 카드와 성장 해금의 가벼운 햅틱·미세 동작
- 로딩 스켈레톤과 캐시 갱신 시간의 더 세밀한 표현
- 식사 유형별 추가 교육 문구와 보호자용 주간 회고
- 음식 아이콘 카테고리 확장과 계절별 숲 장식
- DateFormatter 정적 재사용 등 측정 기반 성능 정리
- 네 장을 넘는 스토어 실험 세트와 카피 A/B 검증

P2는 이번 범위의 필수 조건이 아니며 P0/P1 데이터 모델을 미리 복잡하게 만드는 이유로 사용하지 않는다.

## 화면별 권고안

### 오늘의 숲

- 상단 첫 화면은 선택 날짜, 실제 급식, 오늘의 한 가지 미션, 기록 CTA 순서로 구성한다.
- 오프라인 안내는 항상 큰 카드로 두지 않고 캐시 상태 배지나 갱신 안내로 축소한다.
- 숲·마스코트는 유지하되 급식 정보가 배경 장식보다 먼저 읽히게 한다.

### 급식 달력

- 일간, 주간, 월간은 서로 다른 데이터 모델이 아니라 같은 dateKey의 다른 탐색 표면이다.
- 주간은 7일, 월간은 7열을 유지한다.
- 셀에는 대표 메뉴 1–2개와 추가 개수만 표시하고 전체 내용은 공통 상세에서 읽는다.

### 날짜 상세

- 날짜·학교·데이터 상태를 먼저, 메뉴 목록과 영양 총량을 다음, 기록 CTA를 마지막에 둔다.
- NEIS 전체 급식의 정량 값은 출처와 함께 표시할 수 있지만 메뉴별 정량으로 분해하지 않는다.
- 실패와 급식 없음에 각각 다른 안내와 재시도 행동을 제공한다.

### 식사 기록

- 상태 선택과 저장 사이에 “이 음식에서 이런 영양소를 만나요” 확인을 둔다.
- “다 먹었어요”는 먹지 않은 영양소가 없다고 단정하지 않는다.
- “한 입”과 “절반”은 대표 영양소 경험을 격려하되 섭취량을 계산하지 않는다.
- “어려웠어요”는 같은 급식 안의 안전한 대체 메뉴가 있을 때만 제안한다.
- 알레르기 회피는 실패나 패널티가 아니라 안전한 선택으로 표현하고 XP 불이익을 주지 않는다.

### 성장·도감

- 현재 XP, 현재 단계, 다음 임계값, 12단계 전체 위치를 하나의 계층으로 보여 준다.
- 8–12단계는 1–7 몸체 일관성을 유지하면서 액세서리·배경·프레임으로 명확히 구분한다.
- 아직 준비되지 않은 후반 그림은 동일 이미지를 “새 캐릭터”로 반복하지 않고 검증된 대체 상태로 표시한다.
