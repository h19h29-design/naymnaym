# 급식레벨업 1.2 도감·급식표 디자인 명세

## 목표

기존 1.2 변경(앱 이름·아이콘·일간/주간/월간 급식표·알레르기 이름 표시·버전 상향)을 보존하면서, 급식 기록을 캐릭터 14단계와 배지 36종 수집으로 연결한다. iOS와 Android는 같은 계약·동일한 해금 결과를 사용한다.

## 오늘 화면

- 숲 배경 위에 `오늘 급식` 헤더와 캐릭터 성장 허브를 배치한다.
- 캐릭터 허브는 캐릭터, 한 줄 응원, 현재 레벨, 총 XP, 다음 단계 진행을 한 카드로 합친다. 별도 성장 요약 카드는 두지 않는다.
- 하단 탭은 `오늘 · 급식표 · 성장 · 도감 · 설정`의 5개를 유지한다.
- 설정은 기존 설정 화면을 재사용하며 새 개인정보·광고·추적 SDK를 추가하지 않는다.

## 급식표

- 일간·주간·월간 세그먼트를 유지한다.
- 월간은 메뉴가 선택 전에도 보이고, 날짜를 누르면 선택 표시가 갱신된다.
- 주간은 요일 헤더와 해당 열의 메뉴 셀을 눌러 선택일을 바꿀 수 있다.
- 주간·월간 하단의 영양·알레르기 카드는 평균이 아니라 **선택한 날짜 한 끼**만 표시한다.
- 선택일에 급식이 없으면 `해당 날짜의 영양 정보가 없어요.`를 표시하고 다른 날짜 값을 대신 보이지 않는다.

## 도감 A안

상단에는 `전체 수집 n / 50`, 현재 캐릭터, 다음 캐릭터까지 필요한 XP를 표시한다. 탭은 `캐릭터 14`, `영양 탐험 12`, `식사 도전 12`, `꾸준함 12`다. 캐릭터는 2열 카드, 잠긴 캐릭터·배지는 따뜻한 회갈색 실루엣과 해금 조건을 표시한다.

알레르기 회피·`오늘은 어려워요` 기록은 긍정 섭취 배지에 포함하지 않는다. `oneBite`, `half`, `finished`만 긍정 섭취다.

## 공통 성장 계약

`growth-policy.json`은 14개의 strictly increasing threshold와 unique title을 사용한다.

| 레벨 | 제목 | 누적 XP |
|---:|---|---:|
| 1 | 냠냠 새싹 | 0 |
| 2 | 한 입 탐험가 | 80 |
| 3 | 냠냠 용사 | 180 |
| 4 | 편식 몬스터 사냥꾼 | 320 |
| 5 | 급식 히어로 | 500 |
| 6 | 영양 마스터 | 720 |
| 7 | 레전드 냠냠러 | 1,000 |
| 8 | 숲길 수호자 | 1,400 |
| 9 | 제철 탐험대장 | 1,850 |
| 10 | 균형 식판 장인 | 2,350 |
| 11 | 초록별 수호대장 | 2,900 |
| 12 | 영양 수호대장 | 3,500 |
| 13 | 황금 도토리 대장 | 4,150 |
| 14 | 급식 전설 | 4,850 |

7단계가 넘어도 기존 에셋에 기대지 않고 1.2에 포함된 단계별 아트를 사용한다.

## 공통 배지 정책

공통 `collection-policy.json`에 식품군 키워드와 36개 배지를 둔다. 배지 계산기는 다음 지표만 사용한다: 긍정 기록, 완식, 한 입, 새로운 메뉴, 식품군별 기록, 서로 다른 식품군, 하루 세 메뉴, 기록일, 평일 연속 기록일.

| 카테고리 | 12개 기준 |
|---|---|
| 영양 탐험 | 채소 1/5/15, 단백질 1/5, 유제품 1/5, 과일 1/5, 3식품군, 4식품군, 긍정 기록 25 |
| 식사 도전 | 첫 긍정 기록 1, 한 입 1/5/20, 완식 1/5/20, 새 메뉴 3/10/30, 하루 3메뉴 3/10일 |
| 꾸준함 | 기록일 1/3/7/14/30/60, 평일 연속 기록 2/3/5/10/20/40 |

평일 연속 기록은 월요일부터 금요일만 연결하고 토·일은 끊지 않는다. 휴일은 이번 버전의 로컬 데이터만으로 알 수 없으므로 연속성을 끊는다.

## 데이터 계약

- iOS Core Data와 Android Room에서 삭제되지 않은 `meal_records` 전체를 읽는 읽기 전용 소스를 추가한다.
- `CollectionProgress`는 전체 XP, 14단계, 36개 배지 상태, 카테고리별 수집 수를 한 번에 제공한다.
- 계산은 순수 함수여야 하며, 화면은 결과만 렌더링한다.
- 기존 식사 저장 방식과 XP 지급 상한은 바꾸지 않는다.

- iOS `MARKETING_VERSION=1.2`, `CURRENT_PROJECT_VERSION=33`
- Android `versionName "1.2"`, `versionCode 13`
- iOS tests/build, Android tests/lint/debug/release AAB, 릴리스 검증 스크립트를 통과한 후보만 준비 완료로 기록한다.
- 스토어 업로드는 별도 명시 요청 없이는 수행하지 않는다.

## 수용 기준

1. 두 플랫폼의 14단계 XP 경계가 공통 계약과 일치한다.
2. 동일한 식사 기록 집합이 두 플랫폼에서 동일한 36개 배지 상태를 만든다.
3. 주간·월간 선택일이 영양·알레르기 카드와 함께 갱신되고, 급식 없는 날짜는 빈 상태를 표시한다.
4. 하단 설정 탭이 있고 오늘 화면 성장 정보가 캐릭터 카드에 통합된다.
5. Figma에 원본 아트·컴포넌트·A안 적용 화면이 있고 기존 보드는 보존된다.
6. iOS 1.2(33), Android 1.2(13) 릴리스 후보가 검증 증거와 함께 기록된다.
