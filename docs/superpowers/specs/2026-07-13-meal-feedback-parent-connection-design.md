# 급식 피드백 단순화 및 보호자 연결 상태 개선 설계

## 목표

급식 기록의 첫 선택을 `한입도전`, `잘먹어요`, `못먹겠어요` 세 가지로 단순화한다. 기존의 세부 기록, XP, 알레르기 안전, 부모 공유 데이터는 유지하면서 아이가 메뉴마다 망설이지 않고 기록할 수 있게 한다.

보호자 연결이 완료된 뒤에는 초대 대기 안내를 제거하고, 아이와 보호자 양쪽에서 현재 연결 상태와 연결 인원을 즉시 이해할 수 있게 한다. 설정 화면에서는 서버 구현 세부 정보를 노출하지 않는다.

## 범위

- iOS와 Android의 오늘 급식 행동을 같은 용어와 의미로 정리한다.
- 기존 `EatingStatus` 저장 형식과 XP 정책은 유지한다.
- iOS의 영양소 안내, 게임 스탯, 캐릭터 에셋을 재사용한다.
- 보호자 연결 서버와 빌드 설정은 유지하되 사용자 화면에서 서버 주소와 구현 기술을 숨긴다.
- 아이 기기의 연결된 보호자 수는 현재 서버 계약상 연결 여부를 기준으로 `0명` 또는 `1명`으로 표시한다.
- 부모 기기의 연결된 아이 수는 저장된 `ParentProfile.childLinks` 중 실제 연결된 항목 수로 표시한다.

## 검토한 대안

### 1. 버튼 문구만 변경

변경량은 작지만 `못먹겠어요` 아래의 냄새, 어려운 이유, 안전 회피 기록을 자연스럽게 받을 수 없다. 기존 XP와 부모 리포트의 정보 품질도 떨어진다.

### 2. 세 가지 기본 행동과 상세 안내 화면

기본 화면은 단순해지고, 필요한 경우에만 세부 상태를 선택한다. 기존 데이터 모델과 XP 정책을 유지할 수 있으며 알레르기 안전도 보존된다. 이 안을 채택한다.

### 3. 저장 모델을 세 상태로 축소

과거 기록 마이그레이션과 부모 공유 계약 변경이 필요하다. `smelledOnly`, `allergyAvoided` 등 성장과 안전에 필요한 정보를 잃으므로 채택하지 않는다.

## 오늘 급식 화면

### 메뉴별 행동

각 메뉴 카드는 다음 세 버튼만 표시한다.

1. `한입도전`
   - 안전 메뉴는 즉시 `EatingStatus.oneBite`로 기록한다.
   - 알레르기 위험 메뉴에서는 잠금 상태로 표시하고 안전 안내 화면으로 연결한다.
2. `잘먹어요`
   - `EatingStatus.finished`로 기록한다.
   - 기존 기록 XP와 균형 XP 계산을 그대로 적용한다.
3. `못먹겠어요`
   - 즉시 기록하지 않고 `MealDifficultyGuideView`를 연다.

기존 `안내 보기`와 `먹은 정도` 버튼은 카드에서 제거한다. 영양소 안내는 `못먹겠어요` 상세 흐름으로 통합하고, 기존 사진 및 상세 기록 기능은 상세 화면의 보조 기능으로 유지한다.

### 못먹겠어요 상세 흐름

상세 화면은 아이를 설득하거나 압박하지 않는 순서로 구성한다.

1. 메뉴명과 친근한 문구
2. `NutritionEstimator.makeStudentExplanation` 기반 영양소 설명
3. `NutritionEstimator.makeGameStats` 기반 성장 효과
4. 작은 단계 제안
   - 냄새만 맡아도 도전이라는 점
   - 오늘 어렵다고 기록해도 괜찮다는 점
5. 기록 선택
   - `냄새만 맡아봤어요` -> `.smelledOnly`
   - `오늘은 어려워요` -> `.difficultToday`
   - `알레르기·주의로 피했어요` -> `.allergyAvoided`
6. 어려운 이유 선택
   - 기존 `DifficultyReason` 다중 선택을 재사용한다.
7. 안전 메뉴에만 `그래도 한입도전` 선택을 제공한다.

알레르기 위험 메뉴는 영양 도전 문구보다 안전 경고를 먼저 보여준다. `한입도전`은 계속 잠그고, `.allergyAvoided`를 기본 선택으로 사용한다.

### 다 잘먹어요

오늘 급식 데이터가 있을 때 메뉴 목록 위에 `오늘 급식 다 잘먹었어요` 버튼을 표시한다.

- 알레르기 위험이 아닌 모든 메뉴를 `.finished`로 기록한다.
- 알레르기 위험 메뉴는 먹은 것으로 기록하지 않고 기존 기록도 덮어쓰지 않는다.
- 위험 메뉴가 없으면 `오늘 급식을 모두 잘 먹었어요!`로 칭찬한다.
- 위험 메뉴가 있으면 `주의 메뉴를 제외한 오늘 급식을 잘 먹었어요!`로 정확히 안내한다.
- 일괄 기록도 기존 하루 XP 상한을 적용한다.
- 완료 후 현재 성장 단계의 캐릭터를 축하 포즈로 보여주고, `mascot_success` 애니메이션 또는 성장 캐릭터 celebrate 포즈를 재사용한다.
- 중복 탭은 같은 날짜와 메뉴의 기록을 갱신하거나 무시하여 XP가 반복 지급되지 않게 한다.

## 보호자 연결 상태

### 아이 화면

- 연결 전: 초대 방법과 초대 버튼을 표시한다.
- 서버 등록 후 연결 전: `보호자 연결 대기 중`을 표시한다.
- 연결 완료: `보호자와 연결되었습니다`와 `연결된 보호자 1명`을 큰 성공 카드로 표시한다.
- 연결 완료 후에는 `보호자 초대를 기다리고 있어요`, 초대 링크 만들기, 등록 유도 문구를 표시하지 않는다.
- 연결 상태 새로고침은 성공 카드의 보조 동작으로 유지한다.

### 부모 화면

- 연결된 아이가 없을 때만 연결 요청과 코드 입력 안내를 표시한다.
- 한 명 이상 연결되면 `아이와 연결되었습니다`와 `연결된 아이 N명`을 큰 성공 카드로 표시한다.
- 각 아이 이름과 학교, 공유 기록을 기존 카드에서 확인한다.
- 연결 완료 화면에서는 등록 대기 문구를 표시하지 않는다.

### 등록 완료 강조

아이의 초대 화면에서 서버 등록이 완료되면 작은 캡슐 대신 카드 폭의 성공 배너를 표시한다.

- 제목: `초대 링크 준비 완료`
- 설명: `부모에게 링크를 보내면 앱에서 바로 연결할 수 있어요.`
- 행동: `링크 공유`, `링크 복사`

부모가 코드를 연결한 직후에도 같은 수준의 성공 화면을 사용한다.

## 설정 화면

프로필 섹션 아래에 역할별 `연결 상태` 섹션을 추가한다.

- 아이 모드: `연결된 보호자 0명` 또는 `연결된 보호자 1명`
- 부모 모드: `연결된 아이 N명`
- 상태 행을 누르면 기존 보호자 연결 또는 보호자 요약 화면으로 이동한다.

다음 사용자 노출을 제거한다.

- `서버 설정` 진단 행
- Supabase, Edge Function, 서버 주소 등 구현 기술 문구
- 일반 사용자가 해석할 수 없는 `childShareLink`, 업로드 키 같은 진단 이름

오류 해결에 필요한 `초대 코드`, 마지막 동기화 결과, 최근 오류는 사용자 친화적 이름으로 유지한다. 앱 내부의 `PARENT_SYNC_API_BASE_URL` 설정과 서버 연결 코드는 삭제하지 않는다.

## 데이터 및 XP

- `EatingStatus`와 저장 JSON 형식은 변경하지 않는다.
- 세 가지 기본 행동은 기존 상태로 매핑한다.
- 기존 `LevelUpXPPolicy`의 일일 상한을 우회하지 않는다.
- 일괄 기록은 메뉴별 기록 API를 재사용하되 하나의 일괄 결과를 반환한다.
- 이미 기록된 메뉴의 상태를 갱신할 때 같은 행동에 대한 XP를 다시 지급하지 않는다.
- 부모 공유가 활성화된 경우 일괄 기록 결과도 기존 공유 권한 정책을 따른다.

## Android 동등성

- 메뉴마다 세 버튼을 표시한다.
- `못먹겠어요`는 AlertDialog 또는 별도 화면에서 영양소 안내와 세부 상태를 선택한다.
- `오늘 급식 다 잘먹었어요`는 안전 메뉴만 일괄 기록하고 축하 이미지를 표시한다.
- 연결 완료 카드는 대기 문구를 대체한다.
- Android가 부모 연결 목록을 영구 저장하지 못하는 현재 구조는 연결 결과 저장을 보강한 뒤 부모 쪽 연결 인원을 표시한다.
- 서버 주소와 구현 기술은 사용자 화면에 표시하지 않는다.

## 테스트 전략

### 단위 테스트

- 세 행동이 각각 `.oneBite`, `.finished`, 상세 선택 상태로 매핑되는지 확인한다.
- 알레르기 위험 메뉴에서 한입도전이 `.allergyAvoided` 이외 상태로 저장되지 않는지 확인한다.
- 일괄 기록이 안전 메뉴만 `.finished`로 처리하는지 확인한다.
- 일괄 기록의 중복 XP와 일일 상한을 확인한다.
- 연결 완료 상태에서 대기 문구와 초대 행동이 숨겨지는지 확인한다.
- 역할별 연결 인원 표시값을 확인한다.
- 설정 진단 데이터에 서버 구현 문구가 노출되지 않는지 확인한다.

### UI 및 빌드 검증

- iPhone 16과 iPhone SE에서 세 버튼과 상세 화면 줄바꿈을 확인한다.
- 전체 기록 축하 이미지가 화면과 겹치지 않는지 확인한다.
- 아이 연결 전, 대기 중, 연결 완료 상태를 각각 확인한다.
- 부모 미연결, 한 명 연결, 여러 명 연결 상태를 확인한다.
- Android 소형 및 일반 화면에서 같은 흐름을 확인한다.
- iOS `test_sim`, Android unit/lint/build, `git diff --check`를 실행한다.

## 완료 기준

- 오늘 급식 카드의 주 행동이 세 가지로만 보인다.
- `못먹겠어요`에서 영양소와 성장 동기를 확인하고 세부 상태를 저장할 수 있다.
- 일괄 잘먹기와 칭찬 이미지가 안전 정책 및 XP 상한을 지킨다.
- 연결 완료 후 대기 문구가 양쪽 모두 사라진다.
- 설정에서 역할별 연결 인원이 보이고 서버 설정값은 노출되지 않는다.
- iOS와 Android에서 기능 및 문구가 일치한다.
