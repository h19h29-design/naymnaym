# 냠냠레벨업 앱인토스 무료 MVP 설계

## 목표

냠냠레벨업의 핵심 식습관 경험을 만 14세 이상 중·고등학생이 토스 앱 안에서 사용할 수 있는 비게임 미니앱으로 출시한다. 첫 버전은 학교 검색, 오늘 급식, 세 가지 식사 기록, 알레르기 안전, 캐릭터 성장, 체험 모드만 제공한다.

출시와 초기 운영에 현금 비용이 들지 않게 한다. 사용자 데이터는 기기에만 저장하고, 서버는 NEIS API 키를 보호하는 무료 Supabase Edge Function 하나만 사용한다.

## 사용자와 성공 기준

### 주 사용자

- 토스 미니앱을 이용할 수 있는 만 14세 이상 중학생과 고등학생
- 학교 급식을 확인하고 부담 없이 `한입도전`, `잘먹어요`, `못먹겠어요`를 기록하려는 사용자

### 성공 기준

- 사용자가 첫 실행에서 학교와 알레르기를 설정하고 오늘 급식을 확인할 수 있다.
- 실제 급식 메뉴마다 세 가지 행동 중 하나를 기록할 수 있다.
- 알레르기 위험 메뉴에서는 한입도전을 할 수 없고 안전 안내가 먼저 보인다.
- 기록에 따라 기존 냠냠레벨업 XP 규칙과 캐릭터 성장이 반영된다.
- 앱을 종료하고 다시 열어도 같은 기기에서 프로필과 기록이 유지된다.
- 실제 급식, 체험 데이터, 급식 없음, 캐시 데이터, 조회 오류가 서로 다른 상태로 표시된다.
- NEIS API 키와 사용자 로컬 데이터가 앱 번들, 응답, 로그에 노출되지 않는다.
- 유료 토스 기능이나 유료 인프라 없이 샌드박스와 실제 토스 QR 테스트를 통과한다.
- 앱인토스 비게임 검수 체크리스트의 운영, 기능, 디자인, 보안 항목을 충족한다.

## 전역 제약

- 앱인토스 SDK 2.x의 WebView 런타임을 사용한다.
- React와 TypeScript로 별도 미니앱 클라이언트를 만든다.
- 토스 디자인 시스템을 기본 UI로 사용하고 냠냠 캐릭터와 브랜드 색상은 보조 요소로 사용한다.
- 기존 iOS와 Android 앱의 동작과 출시 상태를 변경하지 않는다.
- 사용자 별명, 학교, 알레르기, 식사 기록, XP, 레벨을 서버에 저장하지 않는다.
- 사용자 회원가입, 토스 로그인, 결제, 광고, 프로모션, 스마트 발송, 푸시를 사용하지 않는다.
- Supabase Database, Auth, Storage, Realtime을 사용하지 않는다.
- Supabase 무료 요금제를 유료 요금제로 자동 전환하지 않는다.
- 무료 한도 초과 시 기능을 일시 제한하고 결제를 발생시키지 않는다.
- 실제 학교 조회 실패 시 체험 데이터로 자동 전환하지 않는다.
- 압축 해제한 앱 번들은 100MB 미만이어야 한다.
- 앱 핵심 기능을 외부 웹사이트나 기존 네이티브 앱 설치로 넘기지 않는다.

## 검토한 접근

### 1. WebView React·TypeScript와 Supabase Edge Function

토스 TDS를 사용해 미니앱 화면을 만들고 NEIS 요청만 무료 Edge Function으로 중계한다. 일반 웹 기술과 기존 이미지·Lottie 자산을 활용할 수 있고, 네이티브 모듈 의존성이 없어 첫 검수와 유지보수가 단순하다.

이 접근을 채택한다.

### 2. React Native 미니앱

네이티브 수준 애니메이션과 제스처에 유리하지만 지원 가능한 네이티브 모듈을 확인해야 하고 구현·빌드 범위가 커진다. 핵심 MVP에는 필요하지 않으므로 채택하지 않는다.

### 3. 클라이언트에서 NEIS 직접 호출

서버 함수가 필요 없지만 빌드 결과물에서 NEIS API 키를 추출할 수 있다. 키 보호와 요청 통제가 불가능하므로 채택하지 않는다.

## 시스템 구조

```text
토스 앱
  └─ 냠냠레벨업 WebView 미니앱
       ├─ 토스 Storage: 프로필·알레르기·기록·XP·급식 캐시
       ├─ 번들 자산: 캐릭터·이미지·체험 급식
       └─ HTTPS
            └─ Supabase Edge Function: neis-proxy
                 └─ NEIS 학교기본정보·급식식단정보 API
```

### 미니앱 클라이언트

저장소 루트에 `apps-in-toss/`를 추가한다. 토스가 `.ait` 번들을 CDN에 호스팅하므로 별도 웹 서버는 두지 않는다.

클라이언트는 다음 책임만 가진다.

- 온보딩과 프로필 편집
- 학교 검색과 오늘 급식 조회
- 급식·체험·오류 상태 표시
- 알레르기 위험 판단
- 식사 행동 기록과 XP 계산
- 캐릭터 성장 표시
- 로컬 저장과 삭제

### NEIS 중계 함수

`supabase/functions/neis-proxy/`에 별도 Edge Function을 둔다. 함수는 `searchSchools`와 `fetchMeals` 두 작업만 허용하며, 사용자가 전달한 임의 URL이나 NEIS 경로를 대신 호출하지 않는다.

함수는 다음 책임만 가진다.

- 요청 JSON과 문자열 길이 검증
- 교육청 코드, 학교 코드, 날짜 형식 검증
- Supabase Secret에서 NEIS API 키 읽기
- 허용된 NEIS API 호출
- NEIS 응답을 앱 전용 응답으로 정규화
- API 키와 민감한 내부 오류를 제거한 응답 반환
- 토스 운영, QR 테스트, 승인된 로컬 개발 origin에만 CORS 허용

Supabase DB나 사용자 식별자는 사용하지 않는다.

## 화면과 사용자 흐름

### 첫 실행

첫 실행에서는 다음 순서로 로컬 프로필을 만든다.

1. 냠냠레벨업 소개와 체험 모드 진입
2. 중학생 또는 고등학생 선택
3. 별명 입력
4. 학교명 검색과 학교 선택
5. 알레르기 번호 선택
6. 오늘 급식 화면 진입

별명은 화면 안에서만 사용하며 서버 요청에 포함하지 않는다.

### 오늘 급식

홈 화면은 다음 순서로 구성한다.

1. 현재 캐릭터, 레벨, XP 진행률
2. 선택한 학교와 날짜
3. 데이터 상태 배지
4. 오늘 급식 메뉴 목록
5. 메뉴별 세 가지 기록 행동
6. 오늘 기록 요약

데이터 상태 배지는 `실제 급식`, `체험 데이터`, `급식 없음`, `저장된 급식`, `조회 오류`로 구분한다.

### 식사 기록

각 메뉴에는 다음 세 가지 행동만 표시한다.

- `한입도전`: 안전 메뉴를 한입 시도한 것으로 기록한다.
- `잘먹어요`: 메뉴를 잘 먹은 것으로 기록한다.
- `못먹겠어요`: 오늘 어렵거나 냄새만 맡은 상태를 선택하는 상세 안내를 연다.

동일 날짜와 동일 메뉴에 같은 행동을 반복해도 XP를 다시 지급하지 않는다. 기록을 변경하면 현재 상태는 갱신하되 이미 지급된 XP를 중복 지급하지 않는다.

### 알레르기 안전

선택한 알레르기 번호가 메뉴에 포함되면 다음 원칙을 적용한다.

- 안전 경고를 영양·도전 문구보다 먼저 표시한다.
- `한입도전`을 잠그고 안전 안내를 연다.
- `잘먹어요` 선택 전에도 학교 안내와 보호자 판단이 우선이라는 안내를 표시한다.
- `못먹겠어요` 상세에서 `알레르기·주의로 피했어요`를 제공한다.
- 앱이 식품 안전을 보장하지 않는다는 면책 문구를 유지한다.

### 성장

기존 냠냠레벨업의 행동별 XP, 하루 XP 상한, 레벨 계산 규칙을 TypeScript로 옮긴다. 홈에서는 현재 레벨, 다음 레벨까지의 진행률, 성장 단계 캐릭터를 표시한다.

레벨업이 발생하면 번들에 포함된 기존 캐릭터 이미지 또는 Lottie 애니메이션으로 축하한다. 새로운 외부 유료 자산은 추가하지 않는다.

### 체험 모드

체험 모드는 첫 화면과 설정에서 사용자가 명시적으로 선택할 때만 시작한다.

- 번들에 포함된 샘플 학교와 샘플 급식을 사용한다.
- 모든 주요 화면에 `체험 데이터` 배지를 표시한다.
- 체험 기록은 실제 프로필의 기록이나 XP에 저장하지 않는다.
- NEIS API 실패나 급식 없음 상태에서 체험 모드로 자동 전환하지 않는다.

### 설정

설정에서는 다음 기능만 제공한다.

- 학교 변경
- 알레르기 변경
- 학년 모드와 별명 변경
- 로컬 데이터 전체 삭제
- 개인정보 처리방침 열기
- 지원 안내 열기

서버 주소, Supabase, Edge Function, API 키 같은 구현 세부 정보는 사용자 화면에 표시하지 않는다.

### 앱 내 기능

비게임 앱 필수 앱 내 기능으로 `오늘 급식 기록`을 등록한다. 해당 스킴은 온보딩이 끝난 사용자에게 오늘 급식 화면을 열고, 온보딩 전 사용자에게는 설정을 완료한 뒤 오늘 급식으로 이어지게 한다.

## 로컬 데이터

토스 SDK의 `Storage`를 사용한다. 앱인토스 환경에서 지원되지 않는 React Native `AsyncStorage`는 사용하지 않는다.

저장 키는 냠냠레벨업 전용 접두사를 사용하고 스키마 버전을 포함한다.

- 프로필: 사용자 모드, 별명, 선택 학교, 알레르기 번호
- 진행: 총 XP, 현재 레벨, 캐릭터 성장 단계
- 식사 기록: 날짜, 학교 코드, 메뉴 이름, 행동, 지급 XP
- 급식 캐시: 학교 코드, 날짜, 조회 시각, 정규화한 급식 데이터

앱 시작 시 저장 데이터를 검증한다. 일부 필드가 손상되었으면 해당 영역만 안전한 기본값으로 복구한다. 전체 JSON을 읽을 수 없으면 손상된 값을 제거하고 사용자에게 다시 설정해야 함을 알린다.

QR 테스트와 실제 출시 환경의 웹 표준 저장소 origin은 다르므로, 서비스 상태에는 토스 `Storage`만 사용한다.

## NEIS 요청 계약

### 학교 검색

요청은 `searchSchools` 작업과 공백을 제거한 학교 검색어를 포함한다.

- 검색어는 한글 또는 허용된 학교명 문자 2자 이상 40자 이하로 제한한다.
- 입력 후 400ms 동안 추가 입력이 없을 때 요청한다.
- 이전 검색 요청이 진행 중이면 취소하거나 최신 요청 결과만 반영한다.
- 응답은 학교명, 교육청 코드, 학교 코드, 지역, 주소, 학교 유형만 포함한다.

### 급식 조회

요청은 `fetchMeals` 작업과 교육청 코드, 학교 코드, 시작일, 종료일을 포함한다.

- 코드는 허용된 영문·숫자 길이를 검증한다.
- 날짜는 `yyyyMMdd` 형식을 검증한다.
- 첫 MVP 화면에서는 오늘 날짜만 요청한다.
- 응답은 날짜, 메뉴, 알레르기 번호, 칼로리, 영양 정보만 포함한다.

### 공통 응답

성공 응답과 오류 응답을 구분하고, 클라이언트가 NEIS 원본 오류 구조를 해석하지 않게 한다.

오류 코드는 다음으로 제한한다.

- `INVALID_REQUEST`: 입력값이 올바르지 않음
- `NOT_CONFIGURED`: 서버에 NEIS 키가 설정되지 않음
- `NO_DATA`: 학교 또는 급식 데이터가 없음
- `NEIS_UNAVAILABLE`: NEIS 또는 네트워크 장애
- `RATE_LIMITED`: 요청 제한 또는 무료 운영 보호가 작동함
- `INTERNAL_ERROR`: 사용자에게 세부 내용을 노출하지 않는 내부 오류

## 캐시와 무료 사용량 보호

- 선택 학교와 오늘 급식은 토스 `Storage`에 저장한다.
- 같은 학교·날짜의 실제 급식은 당일 캐시가 있으면 다시 요청하지 않는다.
- 사용자가 새로고침을 선택하면 한 번 다시 요청할 수 있다.
- 학교 검색은 지연 검색과 최신 요청만 반영하는 방식으로 중복 호출을 줄인다.
- 캐시된 급식을 표시할 때 `저장된 급식` 배지와 마지막 조회 시각을 표시한다.
- 무료 한도나 요청 제한이 감지되면 자동 업그레이드나 결제를 시도하지 않는다.
- 비용이 발생하는 Supabase 기능과 토스 기능을 코드와 출시 체크리스트에서 금지한다.

## 오류 처리

### 급식 없음

정상 응답으로 처리한다. 샘플을 대신 표시하지 않고 해당 날짜에 등록된 급식이 없다고 안내한다.

### 네트워크 또는 NEIS 장애

당일 캐시가 있으면 저장된 급식임을 표시하고 사용한다. 캐시가 없으면 오류 안내와 재시도 버튼을 보여준다.

### API 키 미설정

사용자에게 설정 확인 안내를 표시한다. 출시 준비 검사에서는 `NOT_CONFIGURED` 응답을 출시 차단 오류로 처리한다.

### 요청 제한

잠시 후 다시 시도하도록 안내한다. 유료 요금제나 결제로 유도하지 않는다.

### 로컬 데이터 손상

복구 가능한 필드만 기본값으로 되돌린다. 프로필 핵심 필드를 복구할 수 없으면 온보딩으로 이동한다. 식사 기록 손상 때문에 급식 조회나 설정 화면이 열리지 않는 상태를 만들지 않는다.

## 보안과 개인정보

- NEIS API 키는 Supabase Secret으로만 주입한다.
- 함수는 API 키가 포함된 요청 URL이나 헤더를 로그에 남기지 않는다.
- 서버 로그에 별명, 알레르기, 식사 행동, XP를 기록하지 않는다.
- 클라이언트는 학교 검색과 급식 조회에 필요한 값만 전송한다.
- CORS 허용 목록은 토스 운영 origin, QR 테스트 origin, 명시된 개발 origin으로 제한한다.
- 함수 요청 크기와 필드 길이를 제한한다.
- 임의 URL 프록시, 임의 NEIS 경로, 파일 업로드를 허용하지 않는다.
- 로컬 데이터 삭제는 냠냠 전용 키를 모두 제거하고 메모리 상태도 초기화한다.
- 개인정보 처리방침에는 서버에 사용자 프로필과 기록을 저장하지 않으며, 토스 앱 삭제 또는 기기 변경 시 로컬 기록이 사라질 수 있음을 명시한다.

## 비용 통제

초기 운영비 0원을 유지하기 위해 다음 기능을 사용하지 않는다.

- 토스 로그인
- 토스페이와 인앱 결제
- 인앱 광고
- 프로모션과 비즈월렛
- 스마트 발송과 기능성 푸시
- Supabase 유료 요금제와 유료 애드온
- Supabase Database, Auth, Storage, Realtime
- 외부 유료 모니터링과 CDN
- 유료 이미지, 폰트, Lottie 자산

Supabase 무료 한도에 근접하거나 도달하면 유료 전환 대신 호출량을 줄이거나 서비스를 일시 제한한다. 실제 운영에서 무료 한도로 충분하지 않다고 확인되면 별도 설계와 명시적 사용자 승인 없이 유료 기능을 추가하지 않는다.

## 앱인토스 검수 기준

현재 앱인토스 비게임 출시 가이드를 구현과 출시의 최소 기준으로 사용한다.

- SDK 2.x과 비게임 공통 내비게이션을 사용한다.
- 토스 뒤로가기와 미니앱 자체 뒤로가기를 중복 표시하지 않는다.
- 최초 화면에서 뒤로가기를 누르면 미니앱이 정상 종료된다.
- 브랜드 로고와 국문 앱 이름이 내비게이션에 정상 표시된다.
- 홈 이동과 `오늘 급식 기록` 앱 내 기능 스킴이 정상 작동한다.
- 핵심 기능이 미니앱 안에서 완결된다.
- 개인정보 처리방침과 지원 페이지가 정상적으로 열린다.
- 사용자 데이터 전체 삭제가 실제로 작동한다.
- 모든 CTA 문구가 동작 결과를 분명히 설명한다.
- 앱 번들 압축 해제 크기가 100MB 미만이다.
- 샌드박스와 실제 토스 QR 환경에서 iOS와 Android를 모두 확인한다.
- 운영과 QR 테스트 origin이 다른 점을 반영해 CORS와 로컬 저장을 각각 검증한다.

최종 승인은 토스의 운영, 기능, 디자인, 보안 검수 결과에 달려 있다. 이 설계는 현재 공개된 심사 기준을 충족하도록 범위를 제한하지만 승인 자체를 보장하지는 않는다.

## 테스트 전략

### TypeScript 단위 테스트

- NEIS 학교와 급식 원본 응답을 앱 모델로 변환한다.
- 메뉴 문자열에서 알레르기 번호를 분리한다.
- 선택 알레르기가 있는 메뉴의 한입도전을 잠근다.
- 동일 날짜·메뉴·행동에 XP를 중복 지급하지 않는다.
- 하루 XP 상한과 레벨 계산이 기존 앱 규칙과 일치한다.
- 실제 기록과 체험 기록이 섞이지 않는다.
- 저장 스키마 검증과 손상 데이터 복구가 동작한다.
- 당일 캐시와 만료 캐시를 구분한다.

### Edge Function 단위 테스트

- 허용된 두 작업만 실행한다.
- 짧거나 긴 학교 검색어를 거부한다.
- 잘못된 학교 코드와 날짜를 거부한다.
- 임의 URL과 임의 NEIS 경로를 거부한다.
- API 키와 내부 오류를 응답이나 로그에 포함하지 않는다.
- 허용되지 않은 origin을 거부한다.
- NEIS 데이터 없음과 장애를 서로 다른 오류로 변환한다.

### 통합 테스트

- 고정된 NEIS 응답 fixture로 학교 검색과 오늘 급식 흐름을 검증한다.
- 배포된 무료 Edge Function으로 실제 학교와 실제 급식을 조회한다.
- QR 테스트와 운영 origin의 CORS 헤더를 검증한다.
- 네트워크 차단 시 당일 캐시와 오류 화면을 확인한다.

### 샌드박스와 실제 토스 테스트

- iOS와 Android에서 온보딩, 학교 검색, 급식 조회, 세 행동 기록을 완료한다.
- 알레르기 메뉴의 잠금과 안전 안내를 확인한다.
- 체험 모드 표시와 실제 기록 분리를 확인한다.
- 앱 종료 후 로컬 데이터 복원을 확인한다.
- 데이터 삭제 후 온보딩으로 돌아가는지 확인한다.
- 앱 내 기능 스킴, 홈, 뒤로가기, 닫기를 확인한다.
- 개인정보 처리방침과 지원 안내를 확인한다.
- 번들 크기와 무료 기능만 사용했는지 출시 검사로 확인한다.

## 출시 순서

1. 토스 콘솔에 비게임 미니앱과 기본 브랜드 정보를 등록한다.
2. WebView 미니앱과 NEIS 중계 함수를 구현한다.
3. 로컬 fixture와 실제 NEIS로 자동 테스트한다.
4. 앱인토스 샌드박스에서 iOS와 Android를 테스트한다.
5. `.ait` 번들을 만들고 실제 토스 QR 환경에서 테스트한다.
6. `오늘 급식 기록` 앱 내 기능을 등록한다.
7. 비게임 출시 체크리스트와 무료 운영 체크리스트를 완료한다.
8. 운영, 기능, 디자인, 보안 검수를 요청한다.
9. 승인된 번들을 출시하고 Supabase 무료 사용량과 오류만 모니터링한다.

## 범위 밖

다음 기능은 첫 MVP에 포함하지 않는다.

- 초등학생 모드
- 보호자 모드와 보호자 연결
- 서버 기반 사용자 동기화
- 토스 로그인과 익명 사용자 식별키
- 주간·월간 급식 달력
- 사진 촬영과 사진 기록
- 배지 전체 목록과 상세 성장 리포트
- 공유 카드
- 푸시와 스마트 발송
- 광고, 결제, 구독, 프로모션

후속 기능은 MVP의 검수 통과와 실제 사용성을 확인한 뒤 별도 설계, 계획, 비용 검토를 거쳐 추가한다.
