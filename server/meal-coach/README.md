# 급식레벨업 식단 코치 — 로컬 개발 연결

사용자 승인: 오늘 식단 전체의 하루 한 번 AI 해설과 기기 보관. 이전 선택형 v1 API는 호환 경로로 남아 있다. 이 디렉터리는 공개 운영 서버나 스토어 배포 완료본이 아니다.

## 비밀 설정

`node server/meal-coach/prepare.mjs`가 `~/agent-hub/secrets/meal-coach-go.json`을 권한 600으로 준비한다. 기존 파일은 덮어쓰지 않는다. 사용자는 `apiKey` 값만 직접 입력하고 저장한다. 값은 채팅/명령행/로그/Git에 붙이지 않는다. `clientToken`은 앱 개발 연결 인증용이며 Go 키와 다르다.

키 확인 후 명시적으로 로컬 연결을 활성화할 때 `enabled`를 true로 바꾸고 `node server/meal-coach/serve.mjs`를 실행한다. 파일 위치를 바꿀 때는 경로만 `MEAL_COACH_CONFIG_FILE` 환경변수로 전달한다. 서버는 127.0.0.1:64918에만 바인딩한다. 실행당 최대 20개 제공자 요청, 동시 1개, 15초 타임아웃, 자동 재시도 없음. 재실행하면 개발용 호출 카운터가 초기화되므로 운영 비용 제한으로 사용할 수 없다. Go의 Zen 잔액 자동 사용은 이 코드가 설정하지 않으며 계정에서 별도 확인해야 한다.

앱 개발 설정(Go 키가 아니라 개발용 clientToken 사용): iOS 앱 Application Support/meal-coach-development.json, Android 앱 filesDir/meal-coach-development.json에 `{endpoint,accessToken}`. iOS endpoint는 `http://127.0.0.1:64918/v1/meal-coach`, Android 에뮬레이터는 `http://10.0.2.2:64918/v1/meal-coach`. 설정은 DEBUG에서만 읽는다. 비밀이므로 저장소 밖 앱의 내부 폴더에만 위치시킨다. 키를 준비한 후 설치 절차를 실행하며 현재 배포본에는 포함하지 않는다.

## 데이터 및 안전

- 메뉴명/학교/날짜/이름/개인 식사 기록/등록 알레르기/사진은 전송하지 않는다. 선택한 가정적 질문 종류, 대표 영양소 ID, 임시 세션 UUID를 전송한다. 식단 전체 선택 시에만 확보된 전체 영양량을 포함하며, 개별/부분 메뉴 선택 시 `wholeMeal`은 빈 객체다.
- 개인정보를 제외해도 식단이 개인에 연관될 수 있으므로 공개 배포 전 보호자 동의와 외부 처리 고지 검토가 필요하다. 개발 화면의 전송 동의는 법적 보호자 동의 절차를 대체하지 않는다.
- 등록 알레르기와 겹치는 선택 메뉴는 AI 호출을 하지 않고 로컬 안전 안내를 유지한다. AI 응답이 도전 잠금, 알레르기 원본, 식사 기록, XP를 변경하지 않는다.
- 수치 추정/의료 단정/관련 없는 출력은 지시와 응답 검증으로 제한한다. 문자열 필터는 완전한 안전 보장이 아니며, 공개 운영 전 독립 아동 안전 평가와 강한 출력 통제 검토가 필요하다.
- 실패 시 AI로 가장하지 않는 기본 영양 안내로 복귀한다. 대화/요청/응답 내용은 서버에 저장하거나 로깅하지 않는다. v2는 사용 한도만 최소 SQLite 장부에 보관한다(아래). 공급자의 보관 정책까지 통제한다고 주장하지 않는다.

## 확인한 API 문서

2026-09-13 [OpenCode Go](https://opencode.ai/docs/go/#endpoints): `deepseek-v4.1-flash`, `/zen/go/v1/chat/completions`. OpenCode CLI 별칭을 HTTP 모델 ID로 사용하지 않는다. 서비스 자체의 User-Agent로 식별하며 코딩 에이전트로 위장하지 않는다. Go는 코딩 에이전트용으로 안내되어 있으므로 일반 사용자 식단 서비스 용도 지원 여부는 확인되지 않았다. 공개 운영은 보류한다.

## 테스트

`node --test server/meal-coach/*.test.mjs` — 인증, 스키마, 자유입력/개인필드 거부, 호출 상한/동시성/시간초과, 응답 크기, 비밀 유출, 안전 검증, 비밀 설정 파일 보존. 실제 외부 API 호출 없음.

### 개발 기기 설치와 실연동 검증 (2026-09-13)

- `node server/meal-coach/install-development.mjs ios <SIMULATOR_UUID>` 또는 `android <EMULATOR_SERIAL>`로 설치된 디버그 앱 내부에 개발용 토큰만 생성한다. 원본 Go 키는 복사하지 않는다. 기존 목적지 파일은 덮어쓰지 않는다. iOS 파일과 Android 앱 내부 파일 권한은 600이다.
- 사용자 키 저장 확인 후 실제 Go HTTP 200 및 검증된 응답을 확인했다. iOS 체험 급식의 현미밥 선택 → 동의 → 질문 → 실제 AI 설명 표시를 확인했다. 기존 XP는 변경하지 않았다.
- Android는 `MealNutritionCoachLiveTest`의 합성 메뉴로 동일한 실제 연결/동의/UI 흐름을 검증했다. `-e mealCoachLive 1`을 명시해야만 외부 호출하며 기본 테스트 실행에서는 건너뛴다. 이 옵션은 과금 가능한 실제 요청 한 번을 허용하므로 사용자 승인 범위에서만 사용한다.
- 최종 Android live UI 결과는 1개 통과(4.758초). 앞선 시도들은 AI 라벨 대기 시간초과로 실패했고, 진단 요청에서 Go 200 뒤 응답 검증 거절 → 게이트웨이 502를 확인했다. 생성 답변의 비결정성/거절 빈도는 남은 품질 과제이며 검증 필터를 완화하지 않았다.
- 서버/설치 DTO 테스트 14개 통과. Android 테스트 APK는 기존 한글 클래스패스 우회 스크립트 `-I ../scripts/android-test-classpath.gradle`로 빌드했다. 앱 제품 코드/릴리즈 설정 변경이나 스토어 배포는 하지 않았다.
- 진단용 서버는 종료했고 일반 `serve.mjs`로 복귀했다. 공개 서버가 아닌 이 Mac의 loopback 개발 연결이다. 일반 앱 서비스로 Go를 운영할 수 있는지와 아동 안전/보호자 동의 검토는 별도로 남아 있다.

### 응답 안정성 보완 (2026-09-13, 후속)

- 실패 응답에 고정된 `reason` 코드를 추가했다. 제공자 인증/요청 제한/서버 오류/네트워크/시간 초과와 답변 형식/잘림/크기/수치/식품 안전/의료/근거 오류를 구분한다. 원본 응답이나 예외 메시지는 반환·기록하지 않는다. 앱에는 기존처럼 기본 영양 안내로 전환된다.
- 원인 구분 후 동일한 합성 메뉴로 변경 전 3개 질문을 호출했다. 2개 성공, 1개는 실제 `finish_reason=length`에 해당하는 `answer_truncated`였다. 이전 모든 실패 원인이 같다고 단정하지 않는다.
- JSON 출력 모드와 짧은 한국어 형식 예시를 추가했다. 각 항목은 가급적 60자 이내로 유도하고 출력 한도는 650 → 1100 토큰으로 조정했다. 15초 제한, 16KB 응답 제한, 자동 재시도 없음, 기존 안전 필터는 유지했다. [DeepSeek JSON Output 문서](https://api-docs.deepseek.com/guides/json_mode/)를 참고했으며 해당 옵션이 포함된 실제 Go 요청의 성공을 확인했다.
- 수량이 없는 요청에서 “이 수치”, “해당 함량”, “주어진 수치”처럼 없는 자료를 가리키는 표현을 지침과 서버 검증으로 제한했다. 이 규칙은 일반적인 사실 검증이나 완전한 안전 분류기를 대체하지 않는다.
- 회귀 테스트는 실패 확인 후 구현했다. 서버/개발 설치 테스트 총 16개 PASS. 수정 후 합성 질문 3개 모두 HTTP 200(2.937/2.289/3.494초), iOS 현미밥의 남김 질문 실제 AI 표시 및 스크린샷 확인, Android 명시적 동의 live UI 1개 PASS(7.966초). 수정 후 실제 호출 표본 5개 성공이며 장기 성공률을 보장하는 결과는 아니다.
- 변경한 일반 로컬 서버로 재시작했다. 네이티브 제품 코드는 이번 보완에서 변경하지 않았으며 네이티브 전체 빌드/단위 테스트를 재실행했다고 주장하지 않는다. 커밋·푸시·스토어 배포 없음. 공개 운영 HOLD 유지.

## 하루 식단 AI 해설 v2 (2026-09-13)

- 활성 네이티브 진입은 `오늘 식단 AI 해설`이다. `/v2/meal-coach/daily`로 익명 메뉴 ID와 해당 대표 영양소, 확인된 전체 식사 영양량을 보낸다. 원본 메뉴명/학교/날짜/개인 식사 기록/등록 알레르기는 전송하지 않는다. 알레르기와 겹치는 후보 및 정보 부족 후보는 로컬에서 제외한다.
- 일일 한도는 서버 한국 날짜와 개발 자격 증명을 기준으로 성공 한 번, 실제 제공자 요청 최대 세 번이다. `~/agent-hub/secrets/meal-coach-usage.sqlite`(600)에 해시 식별자·날짜·시도 횟수·상태만 저장한다. 서버 재시작이나 앱 기록 삭제로 일일 한도를 초기화하지 않는다. 이 개발 토큰은 두 시뮬레이터가 공유하므로 운영 사용자별 한도 구현으로 간주하지 않는다.
- 성공 답변은 서버 메모리에서만 90초 동안 동일 요청 재전송에 반환한다. 클라이언트의 익명 pending 요청도 짧은 앱 세션 캐시에 유지하여 화면을 닫았다 다시 열 때 복구한다. 프로세스 종료나 기기 변경 후 미저장 답변 복구는 보장하지 않는다. 결과가 불확실한 서버 pending 상태는 새 생성 없이 fail-closed 처리한다.
- 앱에는 평가 당시 식단/검증된 AI 응답/출처/생성 시각을 Core Data 또는 Room으로 보관한다. 저장 성공 전 완료로 표시하지 않으며 저장 실패는 추가 AI 호출 없이 재저장한다. 현재 알레르기와 관련된 저장 추천도 숨긴다. 식사 기록·XP는 수정하지 않는다.
- 새 서버·설치·동시성·재시작·안전 테스트 총 32개 통과. 동일 영양량의 JSON 키 순서만 달라져도 같은 요청으로 복구하도록 정규화했다. iOS 실제 체험 메뉴로 한 번 생성 후 앱 재실행에서 같은 평가를 다시 열었고, 장부 합계는 시도 1/성공 1이었다. Android의 이 v2 검증은 합성 응답을 사용하며 일일 한도를 우회해 두 번째 실제 호출을 하지 않았다.
- 공개 AI 운영은 HOLD다. Go의 일반 사용자 앱 용도 허용, 운영 인증·사용자별 비용 제한, 아동 안전 평가와 보호자 동의·외부 처리 고지가 별도 출시 조건이다. Debug 개발 연결 외 Release AI 연결은 비활성이다.
